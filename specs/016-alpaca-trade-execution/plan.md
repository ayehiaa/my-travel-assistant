# Implementation Plan: Alpaca Trade Execution

**Branch**: `075-alpaca-trade-execution` | **Date**: 2026-06-19 | **Spec**: [spec.md](spec.md)

## Summary

Allow `premium_plus` users to connect their Alpaca paper trading account and execute the buy/sell `action_list` from a portfolio recommendation directly on Alpaca. Credentials are encrypted AES-256-GCM. Orders use whole-share qty (floor division of delta_usd / ask_price). Sells execute before buys. Results are persisted and displayed permanently on the recommendation page. One execution per recommendation.

## Technical Context

**Language/Version**: TypeScript strict, Node.js 24

**Primary Dependencies**: Next.js 16 App Router, React 19, Supabase, Tailwind CSS v4 (inline styles matching existing portfolio components), Zod, Vitest, Node.js `crypto` module (AES-256-GCM — already used in `gmailCrypto.ts`)

**Storage**: Supabase Postgres — two new tables: `alpaca_credentials`, `alpaca_executions`

**Testing**: Vitest — `src/lib/alpacaOrderCalculator.test.ts` for pure qty calculation logic

**Target Platform**: Vercel / Next.js web app

**Project Type**: Web service module (addition to existing portfolio module)

**Performance Goals**: Preview modal loads within 3s; execution results visible within 5s

**Constraints**: Whole-share orders only (no fractional). One execution per recommendation. Credentials encrypted at rest.

**Scale/Scope**: Single-user feature (`premium_plus`). Portfolio typically 5–15 tickers; at most ~15 sequential Alpaca API calls per execution.

## Constitution Check

**Principle I — Auth-First**: ✅ All three new API routes (`/credentials`, `/preview`, `/execute`) check `supabase.auth.getUser()` as their first operation, return 401 if null.

**Principle II — Zod Validation**: ✅ All request bodies validated with Zod schemas before any business logic or DB access.

**Principle III — Audit Logging**: ✅ Three new `AuditAction` values added. `logAudit()` called in credentials POST, credentials DELETE, and execute POST routes.

**Principle IV — Role-Based Access Control**: ✅ All routes check `role === 'premium_plus'`; return 403 otherwise. Matches existing portfolio route pattern.

**Principle V — Pure-Function Tests**: ✅ `alpacaOrderCalculator.ts` (qty computation, market hours check) is a pure module with co-located `alpacaOrderCalculator.test.ts`.

**Inline styles note**: The existing portfolio components (`ActionList.tsx`, `PortfolioSettingsForm.tsx`, etc.) use inline styles rather than Tailwind classes. This feature follows the same pattern for consistency with the portfolio module's visual style. This is a known deviation from the constitution's "Tailwind only" principle that predates this feature.
