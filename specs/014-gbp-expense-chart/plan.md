# Implementation Plan: GBP-Normalised Expense Chart

**Branch**: `014-gbp-expense-chart` | **Date**: 2026-05-23 | **Spec**: [spec.md](spec.md)

## Summary

Convert all expense amounts to GBP before rendering the expense chart, using historical exchange rates from frankfurter.app (ECB-backed, free, no API key). Conversion is server-side only; stored amounts and currencies remain unchanged. The chart's existing GBP-exclusion logic is replaced with a rate-lookup-and-convert step.

## Technical Context

**Language/Version**: TypeScript strict, Node.js 24 LTS

**Primary Dependencies**: Next.js 16 App Router, React 19, Recharts (existing)

**Storage**: Supabase Postgres (read-only for this feature — no schema changes)

**Testing**: Vitest — unit tests for `currencyConverter.ts` and updated `expenseChartData.ts`

**Target Platform**: Vercel (server components + edge-compatible fetch caching)

**Project Type**: Web application (Next.js App Router)

**Performance Goals**: Chart renders in < 3 s with 10 currencies across 12 months. Achieved via batching: one frankfurter.app call per unique expense date (not per expense).

**Constraints**: No API key. No Anthropic. No DB writes. Historical rates are immutable — cached indefinitely. Same-day rates cached 1 hour.

**Scale/Scope**: Typical user: < 200 expenses, < 5 currencies, < 24 unique dates needing conversion. Worst case: 24 parallel fetch calls.
